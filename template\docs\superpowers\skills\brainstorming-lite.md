# Brainstorming Lite

## Uso

Antes de construir algo nuevo cuando el objetivo, alcance o experiencia no estan claros.

## Proceso

1. Leer contexto minimo del proyecto.
2. Identificar objetivo, usuario, restricciones y criterio de exito.
3. Hacer solo las preguntas necesarias.
4. Proponer 2-3 enfoques si hay decisiones reales.
5. Acordar un diseno breve antes de implementar.

## Adaptacion Codex

- No exige specs largas para tareas pequenas.
- Si la feature es grande, guardar spec en `docs/superpowers/specs/`.
- Para UI, combinar con `ui-designer` o `ux-architect`.

## Salida

- Diseno corto.
- Riesgos.
- Siguiente accion: plan, implementacion directa o investigacion.
