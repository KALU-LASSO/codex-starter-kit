# Test Driven Development Lite

## Uso

Cuando se cambia comportamiento, se corrige un bug o se implementa logica con riesgo.

## Proceso

1. Escribir un test que describa el comportamiento deseado.
2. Ejecutarlo y confirmar que falla por la razon esperada.
3. Implementar lo minimo para pasarlo.
4. Ejecutar test y suite relevante.
5. Refactorizar solo si mejora claridad sin cambiar comportamiento.

## Adaptacion Codex

- En proyectos sin framework de test, usar script de reproduccion o checklist manual.
- En prototipos desechables, pedir o asumir excepcion razonable.
- No bloquear trabajo pequeno de contenido o configuracion con TDD artificial.

## Salida

- Test o verificacion antes/despues.
- Codigo minimo.
- Resultado de comandos.
