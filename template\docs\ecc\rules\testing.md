# Testing Rules

- Cambios de comportamiento necesitan prueba automatica si el proyecto lo permite.
- Bugs importantes necesitan reproduccion o test de regresion.
- Build, lint o tests deben ejecutarse frescos antes de afirmar cierre.
- En UI, verificar flujo real y responsive cuando aplique.
- Si no hay framework de test, usar script, checklist o prueba manual documentada.
- No arreglar tests rompiendo el comportamiento que protegian.
- Reportar pruebas no ejecutadas y motivo.
